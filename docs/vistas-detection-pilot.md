# Vistas设施检测可行性实验
日期：2026-11-11

## 结论与研究贡献
工程可行：现有6GiB显卡成功运行YOLO-World v2 Small，23张开发图片全部完成，无OOM。
效果尚不满足正式研究要求：当前自然语言提示与Vistas目标范围存在不一致，小目标和误检也明显。本轮为研究A建立了可复现推理入口和失败证据，不证明开放词汇泛化成功，也不直接支持研究B的地理定位能力。

## 可复现条件
官方权重：https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8s-worldv2.pt
模型接口说明：https://docs.ultralytics.com/models/yolo-world/
SHA256：9b2c17ab6124a913e9b3a5c170617920d91b0f01111a8479da69f00e2cf27792。
本机Ultralytics8.3.93、PyTorch2.5.1+cu121，沿用已有CLIP缓存，无设施微调、无结构调整。
13个类别（草案8已见+5未见）各按SHA256(pilot-v1+文件名)排序选3张training图，合并去重为23张。对选中图片统计全部13类正面积框标注，非每类只统计3个目标。样本为开发诊断，不代表官方验证集；未使用validation调参。组名仅沿用划分草案，本轮所有类别都未进行任务训练。
输入imgsz960，FP32，batch1，CUDA分配器上限60%，conf0.1，NMS IoU0.7，max_det300。
逐类别按预测置信度贪心一对一匹配，IoU>=0.5；这是固定阈值诊断，不是COCO AP。尚未实现无效框/crowd区域忽略，精确率仅供初步诊断。不得将其作为正式论文主结果。

## 资源
峰值allocated766.01MiB、reserved866MiB（PyTorch口径，不含完整整卡占用）。
去掉首张冷启动后，每图model.predict调用外层同步计时中位数0.108秒，包含该调用的读图/预处理/推理/后处理，不含评测、保存及模型/文本初始化。不是部署承诺。

## 失败与数据检查
抽查30个实例，panoptic RGB解码后的像素面积全部与JSON一致；框按[minx,miny,maxx-minx,maxy-miny]全部匹配。采用包含端点的宽高(+1)则与JSON差1，说明正式转换必须显式固定坐标口径。
case_0.jpg：street light预测覆盖灯杆及灯具，真值主要覆盖灯具，可见目标范围不一致；这解释该案例的IoU失败，不能据此量化全量错误原因。
case_1.jpg：消防栓存在匹配较好的小目标案例。
case_2.jpg：自行车架示例出现漏检及位置不同的预测；外观、定义及标注覆盖仍需进一步复核。
三张图均已目视检查；绿色真值、红色预测。没有据案例反复调提示或选择最佳阈值。

更正此前“643条无效几何”表述：全部643条记录area>0，只是在原JSON框的max-min口径下宽或高为零；不能说它们是损坏标注。此前排除是当前框检测实现的处理选择，会排除极细小目标，可能使样本偏向较易对象。后续从掩膜生成规范的包含端点范围、核查剩余643条像素一致性，决定正式纳入/忽略政策，并更新统计；原始标注保留。本轮结果未修订这一处理以避免混淆实验版本。

## 下一步
1. 先定义Vistas检测对象范围：灯具与杆分开、招牌与Logo分开，形成可追溯类别—英文提示表。
2. 修复框转换与极小目标处理，完善标准AP评测及ignore策略，保留本轮结果作为历史诊断。
3. 在相同开发样本上比较原提示与定义对齐提示；另设独立开发检查样本，避免只记住这23张。
4. 再比较960全图与切片策略，隔离尺度因素。若仍差，再引入第二模型；现在无需结构改造或增加显卡。
