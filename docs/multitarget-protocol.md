# 同场景多目标验证协议 v1
目的：验证指定目标实例是否决定定位结果，连接研究A的实例识别与研究B的位置确定。此协议在新评测前固定。

## 合格样本
同一地面图、同一参考图、至少两个明确可对应的不同实例；每个实例均有地面点击与参考图真值框。图像文件不同但视觉相似不能直接视为同图；参考图裁切不同必须另做坐标映射。
先使用验证集，不基于当前测试集选模型。训练集多目标只能作为机制演示，单列结果。
官方记录中点击与框不同只是候选，需要目视核验，排除同一目标重复点击、近似框和标注冲突。

## 最小人工补标
若缺少官方合格样本，从验证集顺序筛选10个有两个清晰可见、可跨视角确认目标的场景，作为可行性试验。记录所有筛选/排除原因，不能按模型预测挑选。
字段：scene_id、split/index、query/reference、instance_id、类别、query_click_xy、query_region_xyxy（如可标）、reference_box_xyxy、对应依据、遮挡/歧义、annotator、reviewer、review_status。
保留原始官方标注。新标注标记为derived_manual，不覆盖原数据；无法可靠对应则uncertain并排除主指标。独立复核通过后冻结样本清单。
此样本仍是大地物实例实验，不替代真实小设施、Logo代表点数据。

## 成对推理及指标
同图分别输入点击A与点击B，其余输入固定；再做中心提示作为对照。batch1、FP32、分配器上限0.6。
每场景输出2×2 IoU矩阵：预测A与真值A/B、预测B与真值A/B。
报告：单目标IoU>0.5成功率；双目标同时成功场景比例；正确实例偏好比例（各预测与本目标IoU严格大于另一目标）；预测框变化；每个失败案例。
相邻/重叠真值可能使偏好指标产生歧义，需要单列。只发生位移不能算正确切换。样本太少时只报计数和案例，不作显著性或总体泛化结论。

## 后续方法假设
若完整图片+点击条件无效，可先比较目标区域裁剪输入和原图输入，评估局部目标信息与场景上下文的取舍；裁剪改变输入分布，不能与训练过的改进混称。先建立有效实例标注，再执行此对照。
未来小设施使用地面代表点、Logo使用明确入口/立面落地点，并在有可靠地理参考时报告米制误差；不能用本协议建筑框中心替代。
